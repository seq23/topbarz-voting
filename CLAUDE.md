# topbarz-voting

The CultureCon track vote for Top Barz at voting.topbarz.xyz: a static page in `public/` (no framework, no bundler), an API in `functions/api/` (Cloudflare Pages Functions), D1 for tracks, voters, likes and comments, and R2 for the audio and photos, served at `/media/*`. It runs on the Cloudflare Pages project `topbarz-voting` in Sequoia's account (`8d147e242033699dd37c6f5a451f48d2`). **Operating steps and the API a front end calls are in `RUNBOOK.md`; read it before changing anything.**

- **Brand.** "Top Barz" is two words. The slogan is JUMP IN THE BOOTH. Never write "spit your bars". A test fails on any of these in `public/` or `functions/`.
- **The vote.** One like per email per track, a toggle; any number of tracks. Every like and un-like is a row in `like_events` and is never deleted: the count and the tie-break are computed from those rows (`functions/_lib/tally.js`).
- **The end time lives in one place**, `functions/_lib/config.js` (`2026-10-12 06:59 UTC` = Sunday 11 Oct 2026, 11:59 PM PDT). The server rejects likes and comments after it. A test fails if the literal appears anywhere else.
- **Two environments that never share data.** Production (`main` branch; D1 `topbarz-voting`, R2 `topbarz-voting-media`) and preview (every other branch, `staging` is the stable one; D1 `topbarz-voting-preview`, R2 `topbarz-voting-media-preview`). Test tracks and test photos go to preview only: the loaders refuse a "Test …" folder or file for production.
- **Scooter Taylor's own track is never in the vote.** `scripts/load-tracks.mjs` excludes any file named for him and switches off any such row it finds; `scripts/promote-booth.mjs` refuses his booth file. The name rule is one function, `functions/_lib/exclusions.js`.
- **Voter data never enters the repo.** The API never returns an email to anyone but the person who typed it (the booth's `you.email`, 4 Oct 2026, is the one case; the vote's API returns none), and the only place one is sent is the mail service, to deliver that voter's own code; comments show a first name only. `npm run export` and `npm run booth-log` write to `exports/` (git-ignored).
- **Secrets.** `VOTER_TOKEN_SECRET`, `GIPHY_BETA_KEY` and `RESEND_API_KEY` are Pages secrets, never in a file or on a command line. With no Giphy key the GIF routes answer `{available:false}` and `/api/state` says so.
- **Email verification.** The gate emails a 6-digit code before it gives a token (`EMAIL_VERIFICATION` in `wrangler.toml`, on in both environments; `functions/_lib/verify.js`). At most 50 code emails in any 24 hours (production 35, staging 15; in each, the last 5 are kept for the team's `/team` sign-in codes), written once in `functions/_lib/config.js`: the mail account is shared. A vote is never lost to mail (budget spent or mail down lets a never-verified email in, marked unverified), and an already-verified email never gets a token without a code. `tests/verify-guard.test.mjs` fails if any path hands a token to a voter who has not entered their code.
- **The select page (`/select`).** Hear the beats, pick one, done; the Waitwhile redirect lands people there after the booth. Beats are their own table (`beats`), their own loader (`npm run load-beats`) and their own route (`GET /api/beats`): a beat is never in `/api/state`, the tally or the export (`tests/beats.test.mjs`). The pick is kept on the device only (localStorage `tbz.pick`), never sent to the server. Its copy is Top Barz's real copy (3 Oct 2026) in one object, `public/js/select-copy.js`; the two engineer names there may be swapped later, and the test pins the sentence. The page is open to search. Stand-in beats (test files) are staging only. The voting page never links to it. RUNBOOK.md, "The select page".
- **The booth (`/booth`, `/track`, `/listen`).** An engineer drops a finished recording on `/booth` and reads the code to the artist (twelve digits in three groups of four since 27 Nov 2026; the four-digit codes from before still work), who enters it on `/track` WITH their email to hear and download it; `/track-qr` is the printed sign. Every email that enters a code is attached to that track (`booth_people`, `migrations/0006_booth_people.sql`; a group each enter their own email with the same code), and the device remembers only the email (localStorage `tbz.booth.email`), never the code. On `/track` anyone attached can flip **Make public** (off for every track until someone does; "share is anyone's call"), which gives the track a listen page at `/listen/<share_id>` (16 random hex characters, never the code) to Share, and can add album artwork (cut to a 1024 px square JPEG on the device; `/media/booth/art/…`); each person has their own **Count me in for the public vote** switch. **A booth track reaches the vote only through `npm run promote-booth`, and only with everyone's opt-in** (`scripts/promote-booth.mjs`; the verdict is `promoteVerdict` in `functions/_lib/booth.js`: it refuses an unknown code, Scooter Taylor's file, a "Test …" file for production, nobody attached, or anyone attached still out; "voting is everyone's consent"). The client's ask, 4 Oct 2026. No passphrase (the client's call, 3 Oct 2026): the routes are open and kept safe by what they accept (audio only, 100 MB, 60 uploads an hour per IP, 300 a day site-wide, code entries 5 a minute) and by the email: every route that changes a song answers 403 `not_attached` unless that email entered that code. The log (`GET /api/booth/tracks`) is the signed-in team's only (a team token, 401 `team_sign_in` otherwise; 27 Nov 2026), because each row carries its code; an audio key never carries the code (`booth/<32 hex>.<ext>`). An email is never in a URL, never in the log (it carries counts: `people`, `everyone_in`), and never shown to anyone but its owner; the only places it is written are `booth_people` and `exports/booth-people.csv`. Booth tracks are their own tables (`booth_tracks`, `booth_people`), their own R2 folder (`booth/`) and their own routes (`/api/booth/*`): never in `/api/state`, the tally, the export or `/api/beats` (`tests/booth.test.mjs`). Copy in `public/js/booth-copy.js` and `public/js/track-copy.js`. `npm run booth-log` writes the log and the people to `exports/`. RUNBOOK.md, "The booth".
- **The contest entry (`/entry`).** The opt-in page for the Top Barz CultureCon contest (Scooter, 9 Oct 2026; working rules, the final public version follows for go-live): a thank-you, the prize, the official-rules link, and a form (name, city, email, phone, an optional group of up to 10 with their names and emails, a track upload, an "I agree to the official rules" box the server insists on). Its own tables (`entries`, `entry_members`, `entry_uploads`), its own R2 folder (`entries/`, never served), its own routes (`/api/entries`, `/api/entries/upload`): never in `/api/state`, the tally, `/api/beats` or the booth, and no route answers an email, a phone number or a name. An entry reaches the vote only through `npm run promote-entry`, which refuses Scooter Taylor, a "Test …" entry for production and an entry without the rules agreement. `noindex` until go-live; not linked from the voting page. Copy in `public/js/entry-copy.js`. RUNBOOK.md, "The contest entry".
- **The holiday party (`/join`, `/team`, the song on `/track`; Scooter, 17 Nov 2026, rebuilt to his consolidated revision list of 18 Nov 2026, which wins over his earlier notes).** Behind `HOLIDAY_EVENT` in `wrangler.toml`: on for preview, off for production until Scooter says go live. Everyone signs up on their own (one stable record per person; one active place per email; Get back in line once their song is uploaded). The ambassador taps each person into the booth and out on `/team`; those taps make a recording (`party_takes`), which reaches the upload station only when its last person is out, and the engineer's next upload lands on exactly its people (`x-party-take`; no picking at upload, 409 `take_changed` if the page is stale). Songs attach by the person's record (`booth_people.guest_id`), never by a typed email; the team can re-point a song with a note, kept in `booth_repoints`; stale and test sign-ups are flagged with email and phone before they move. Typing a song's code with any email hears, downloads and shows who has access; it never puts anyone on the song. **Everyone on the song holds its controls** (Scooter, 19 Nov 2026; this replaced the first-come manager): artwork, title, the entry and Share, for every email on it and nobody else (403 `not_attached`). A recording stays open until its upload, so a group recording one after another is one song (the team's green tap asks "same song or new?" when the booth is empty, 409 `which_song`), and the booth page shows the names for the engineer to confirm before the file goes up (`x-party-take: <take>.<people>`). The entry is the whole song's: anyone on it enters or withdraws it for everyone, every change is a row in `booth_contest_changes` (`migrations/0015_contest_changes.sql`), the track page says who last did it and when, and a withdrawn song keeps its votes. A tick puts it in the vote by itself (`contestVerdict`; preview only until Scooter settles the waiver question; Scooter Taylor and test files in production refused as ever, in neutral words). While the party is on, a like counts only once its email entered the 6-digit code (`countedLikesClause`). **Voting closes Friday, 27 Nov 2026, 11:59 PM ET** (`PARTY_VOTING_ENDS_AT`, Scooter 19 Nov 2026): the page shows it with the countdown, and a vote counts only if its like and its code are both before it. The prize line reads "Prize details TBD" until he sends the terms. His own songs stay out of the vote; `npm run demo-song` makes a song to demo the entry on preview. Guest phones and emails are answered to the signed-in team only. The partner logos are white marks made by `npm run make-partner-logos`; the rules page is a DRAFT. RUNBOOK.md, "The holiday party".
- **The start time lives in one place too**, `functions/_lib/config.js` (`VOTING_STARTS_AT`, `2026-10-11T14:00:00Z` = Sunday 11 Oct 2026, 10 AM ET). Before it the server refuses likes and comments (403 `voting_not_open`). A test fails if the literal appears anywhere else.
- **Checks.** `npm run check` = `npm test` (every rule, against a real local D1 and R2) + `npm run test:smoke` (every route over HTTP). That is the merge gate (`Validate`, about a minute); there is no browser suite. A changed rule means a rewritten test, at least as strict.
- **Deploy.** Merge with `land <pr>`. A green `Validate` on `main` fires `Deploy`: staging, a live check, then production, then a live check. Never a bare `wrangler deploy`.
